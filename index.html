Etapa 1 — Visão Geral e Requisitos

Objetivo do Projeto

  • Painel web para estudantes e professores.
  • Login, visualização de notas/faltas/horário, lançamentos de notas e gestão de turmas.
  • MVP com persistência local (localStorage).

Público-alvo

Alunos (consultas) e Professores (gestão de turmas e notas).

Funcionalidades (MVP)

  • Login demo (aluno/professor).
  • Navegação por tiles; seções: notas, faltas, horário, documentos, etc.
  • Professores: cadastrar turmas, cadastrar alunos, lançar notas com métricas.

Critérios de Aceitação

  • Login funcional com credenciais demo.
  • Professor cria turmas e cadastra alunos (persistência local).
  • Lançamento de notas com métricas e chamadas gravadas.
  • Interface responsiva.

Arquitetura

Front: HTML/CSS/Vanilla JS. Persistência: localStorage. Font: Poppins.

Etapa 2 — Design, UI e Protótipos

Objetivo

Refinar interface, componentes reutilizáveis, garantir acessibilidade e responsividade. Fornecer protótipos para validação.

Componentes-chave

  • Cards, Nav tiles, Forms, Badges, Buttons primário/secondary
  • Login overlay e listas (grid/list)

Acessibilidade & Responsividade

  • Labels atrelados aos inputs, aria-live para mensagens, foco visível
  • Drawer / overflow para muitos tiles; testar <900px

Recomendações

  • Separar CSS/JS; criar tokens de design
  • Substituir alert() por toasts/modais

Etapa 5 — Entrega, Deploy e Roadmap

Preparação para Deploy

  • Extrair index.html em index.html, styles.css, app.js
  • Static hosting: Vercel / Netlify / GitHub Pages
  • Se backend: Heroku / Render / DigitalOcean

Checklist

  • Separar CSS/JS; README; CHANGELOG; CI
  • Testes e2e (Cypress / Playwright)

Roadmap

  • Autenticação real (JWT / SSO)
  • Backend + persistência (Postgres/Mongo)
  • Uploads seguros, notificações, integrações com portal acadêmico

Segurança

HTTPS, sanitização de inputs, políticas LGPD, armazenamento seguro de arquivos (S3).
